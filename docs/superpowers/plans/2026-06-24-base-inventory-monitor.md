# Base Inventory Monitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Dual Universe Programming Board script that shows base storage-container fill levels on a Screen in a Retro-Synthwave theme, delivered as a paste-ready autoconf `.conf` plus a readable, locally-tested Lua source.

**Architecture:** All display logic lives as pure functions in one source file (`baseinventory.lua`) that exposes a global `BIM` table. The functions take injected dependencies (container handles, a name-resolver, a screen, config), so they run unchanged both in-game (real DU globals) and under a local Lua test runner (stubbed DU globals). A small PowerShell build step wraps that single source into the DU autoconf `BaseMonitor.conf` (slots + `onStart` + `onTimer`), keeping one source of truth.

**Tech Stack:** Lua 5.3 (DU runtime; tests run on locally-installed Lua 5.4, code kept 5.3-safe), DU autoconf YAML, HTML/CSS via `screen.setHTML()`, PowerShell for the build step.

## Global Constraints

- **Single Programming Board.** Output via `screen.setHTML()` only (no render-script mode).
- **Code must be Lua 5.3-safe** (no 5.4-only syntax: no `<close>`, no integer-only assumptions; use `math.floor`).
- **Never crash in-game.** Every DU element read is wrapped in `pcall`; unlinked slots are skipped silently.
- **Containers:** fixed named slots `container1`..`container24`, `class: ItemContainer`, `select: manual`.
- **DU element API used:** container handle `getItemsVolume()` (liters), `getMaxVolume()` (liters), `getItemsMass()` (kg), `getLocalId()`; `core.getElementNameById(localId)`; `screen.setHTML(html)`; `unit.setTimer(tag, seconds)`; `unit.onTimer(tag)`; `system.print(msg)`. All element methods are dot-called (`c.getItemsVolume()`).
- **Theme palette (verbatim):** background `#0d0211`, hot pink `#ff007f`, electric cyan `#00f3ff`, laser yellow `#fffb00`, bright purple `#b10dc9`.
- **Tunables (`--export`):** `refreshSeconds=5`, `warnPct=75`, `critPct=90`, `sortMode="fill-desc"`, `title="BASE INVENTORY"`.
- **Units:** volume in liters auto-scaled L/kL/ML/GL; mass = kg/1000 → tons.
- **Single source of truth:** `BaseMonitor/baseinventory.lua`. `BaseMonitor.conf` is generated by `build.ps1`; never edit `.conf` by hand.
- **Commits are local-only** (run `git init` in Task 0). If the user prefers no commits, the commit step in each task may be skipped without affecting the build.

## File Structure

| File | Responsibility |
|------|----------------|
| `BaseMonitor/baseinventory.lua` | Source of truth: pure logic (format, model, view, app) + DU bootstrap (`BIM.start`/`BIM.tick`), exposes global `BIM`. |
| `BaseMonitor/tests/stubs.lua` | Fake DU globals + fake container handles for local tests. |
| `BaseMonitor/tests/run.lua` | Minimal assert-based test runner; loads `baseinventory.lua` under stubs and asserts behavior. |
| `BaseMonitor/build.ps1` | Generates `BaseMonitor.conf` from `baseinventory.lua` (slots + handlers). |
| `BaseMonitor/BaseMonitor.conf` | Generated paste-ready DU autoconf artifact. |
| `BaseMonitor/README.md` | Slot-linking + container-naming instructions for the player. |

`BIM` table surface (defined in Task 1+, consumed across tasks):

- `BIM.formatVolume(liters) -> string`
- `BIM.formatMass(kg) -> string`
- `BIM.formatPct(pct) -> string`
- `BIM.buildRows(slots, getName) -> rows[]`  where `rows[i] = {label, vol, maxVol, mass, pct, ok}`
- `BIM.sortRows(rows, mode) -> rows[]` (sorts in place, returns it)
- `BIM.aggregate(rows) -> {totalVol, totalMax, pct, count}`
- `BIM.classifyLevel(pct, warnPct, critPct) -> "ok"|"warn"|"crit"`
- `BIM.renderHTML(model) -> string`  where `model = {title, rows, agg, tick, warnPct, critPct, error?}`
- `BIM.run(env) -> string`  where `env = {core, screen, slots, config, tick}`
- `BIM.start()` / `BIM.tick()` (DU bootstrap; read real globals)

```lua
local function round1(n) return math.floor(n * 10 + 0.5) / 10 end

function M.formatVolume(liters)
  liters = liters or 0
  if liters < 1000 then return string.format("%d L", math.floor(liters + 0.5)) end
  if liters < 1000000 then return string.format("%s kL", round1(liters / 1000)) end
  if liters < 1000000000 then return string.format("%s ML", round1(liters / 1000000)) end
  return string.format("%s GL", round1(liters / 1000000000))
end

function M.formatMass(kg)
  return string.format("%.1f t", (kg or 0) / 1000)
end

function M.formatPct(pct)
  pct = pct or 0
  if pct < 0 then pct = 0 elseif pct > 100 then pct = 100 end
  return string.format("%d%%", math.floor(pct + 0.5))
end
```
Note: `round1` drops trailing `.0` for whole numbers because Lua prints `1.0`→`1.0`; `%s` on the number `1.5` yields `1.5` and `2.0`→`2.0`. The tests use values with non-zero decimals to stay deterministic.

```lua
local MAX_SLOTS = 24

local function readContainer(c, getName)
  local localId = nil
  pcall(function() localId = c.getLocalId() end)
  local label = (localId and getName and getName(localId)) or nil

  local vol = c.getItemsVolume()
  local maxVol = c.getMaxVolume()
  local mass = c.getItemsMass()

  if not label then label = "Container " .. tostring(localId or "?") end
  local pct = 0
  if maxVol and maxVol > 0 then pct = (vol / maxVol) * 100 end
  return { label = label, vol = vol or 0, maxVol = maxVol or 0,
           mass = mass or 0, pct = pct, ok = true }
end

function M.buildRows(slots, getName)
  local rows = {}
  for i = 1, MAX_SLOTS do
    local c = slots[i]
    if c ~= nil then
      local ok, row = pcall(readContainer, c, getName)
      if ok then
        rows[#rows + 1] = row
      else
        -- Best-effort label even on failure.
        local localId = nil
        pcall(function() localId = c.getLocalId() end)
        local label = (localId and getName and getName(localId)) or ("Container " .. tostring(localId or "?"))
        rows[#rows + 1] = { label = label, vol = 0, maxVol = 0, mass = 0, pct = 0, ok = false }
      end
    end
  end
  return rows
end
```

```lua
function M.sortRows(rows, mode)
  if mode == "none" then return rows end
  local cmp
  if mode == "fill-asc" then
    cmp = function(a, b) return a.pct < b.pct end
  elseif mode == "name" then
    cmp = function(a, b) return tostring(a.label) < tostring(b.label) end
  else -- "fill-desc" default
    cmp = function(a, b) return a.pct > b.pct end
  end
  table.sort(rows, cmp)
  return rows
end

function M.aggregate(rows)
  local totalVol, totalMax, count = 0, 0, 0
  for _, r in ipairs(rows) do
    if r.ok then
      totalVol = totalVol + (r.vol or 0)
      totalMax = totalMax + (r.maxVol or 0)
      count = count + 1
    end
  end
  local pct = 0
  if totalMax > 0 then pct = (totalVol / totalMax) * 100 end
  return { totalVol = totalVol, totalMax = totalMax, pct = pct, count = count }
end
```

```lua
  if pct >= critPct then return "crit"
  elseif pct >= warnPct then return "warn"

end

  s = tostring(s or "")

function M.renderHTML(model)

  parts[#parts+1] = '<div class="bim"><div class="grid"></div><div class="scanline"></div>'
```

````markdown
# Base Inventory Monitor (Synthwave)

A Dual Universe Programming Board script that shows your base storage containers'
fill levels on a Screen, in a neon Retro-Synthwave theme.

## Install

1. Place a **Programming Board** and a **Screen** on your base.
2. Right-click the board → **Advanced → Run Lua script → paste** the contents of
   `BaseMonitor.conf` (it's a DU autoconf — paste the whole file).
3. With the **Link tool**, link the board to:
   - the **Core** unit  → slot `core`
   - the **Screen**     → slot `screen`
   - each **Container**  → slots `container1`, `container2`, … (any order)
4. Activate the board.

> Only link what you have. Empty `containerN` slots are skipped silently — no errors.
> Up to 24 containers; add more slots in `baseinventory.lua` + rerun `build.ps1` if needed.

## Naming your containers = naming your groups

The script **cannot read what items are inside a container** (DU does not expose that).
The container's **in-game name is the label shown on screen**. Name each container after the
item group it holds, e.g.:

- `T1 Ore`, `Pure T1`, `Light Metal Prod T1-2`, `Heavy Metal Prod T1-2`,
  `Conductor T1-2`, `Plastic`, `Glass`, `Simple Components T1`

If one container holds several groups, give it a joined name yourself, e.g. `Ore + Pure T1`.
The fill bar and mass are always accurate (read as true volume), even for mixed contents.

| `sortMode` | `fill-desc` | `fill-desc`, `fill-asc`, `name`, or `none` |
````
